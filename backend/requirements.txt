# fastapi / starlette are HELD at this version deliberately. Read this before
# bumping them for a CVE report.
#
# The Starlette advisories (CVE-2026-54283, -48818, -48710, -48817, -54282,
# -62727, CVE-2025-54121, CVE-2024-47874) all want a newer Starlette, and the
# upgrade is not safe yet. Measured on 2026-10-19 against the full suite:
#
#   starlette 0.49.3 + fastapi 0.148   9 failed, 3519 passed
#   starlette 1.9.0  + fastapi 0.149   9 failed, 3519 passed
#   ...and slowapi 0.1.10 (the newest) does not change either result.
#
# The same nine fail each time, and two of them matter more than the advisories
# do: tests/test_rate_limits_actually_apply.py shows the global SlowAPIMiddleware
# silently stops applying -- six calls under a 3/minute default all return 200
# instead of the fourth returning 429. Every undecorated route would lose its
# throttle, which is a live abuse surface traded for mostly-DoS and
# Windows-specific advisories. The other seven are route-introspection
# assertions in test_route_access.py and test_secure_upgrades_phase3.py, which
# read the app's route table to prove the public surface is exactly the reviewed
# list; the newer stack changes that table's shape.
#
# So this needs its own piece of work -- understanding the nine, likely
# replacing slowapi -- not a line edit inside a dependency sweep.
#
# protobuf is stuck for a different reason: google-cloud-secret-manager 2.18.0
# and google-cloud-iam 2.14.0 both pin protobuf<5.0.0, so CVE-2026-0994 cannot
# be resolved until those are bumped. A pin here is overridden by their
# resolver, not honoured.
